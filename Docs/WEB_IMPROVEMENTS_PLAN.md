> областям, с привязкой к файлам и критериями проверки. Реализация — задача за задачей,
> сборка затронутого стека и коммит после каждой (без push).

## Группа 1 — Просмотрщики медиа (облако + публичные страницы шаринга)

Все три задачи касаются плееров/вьюверов; разумно делать вместе.

### 1.1 Глобальная громкость видео через cookie (задача 1)
- **Новый файл** `src/lib/volume.ts`: чтение/запись cookie `bark_vol` (уровень `0..1` + флаг `muted`);
  функция `attachVolumePersistence(video: HTMLVideoElement)` — при монтировании выставляет
  `video.volume`/`video.muted` из cookie, на событие `volumechange` сохраняет cookie.
- **Подключение** в каждый `<video>`:
  - `components/media/Lightbox.tsx` (видео в облаке) — через `videoRef`.
  - `pages/PublicViewPage.tsx`, `pages/PublicFolderPage.tsx`, `pages/PublicAlbumPage.tsx` (шаринг) — через `ref`-callback.
- **Проверка:** сменить громкость в одном плеере → открыть другой (в т.ч. на странице шаринга) → громкость та же.

### 1.2 Воспроизведение видео на `/v/{token}` (задача 2)
- **Backend** `WebEndpoints.cs`, эндпоинт `GET /s/{token}/info`: добавить в JSON `downloadUrl = resp.DownloadUrl`
  (temp-URL уже есть в `ResolveShareResponse`, используется редиректом `/s/{token}`). Proto не меняется.
- **Frontend** `pages/PublicViewPage.tsx`: для `mediaKind === 'video'` рендерить встроенный
  `<video src={info.downloadUrl} controls>` (как в публичных папке/альбоме) вместо статичного превью
  с декоративной кнопкой play. Фото и прочие типы — без изменений.
- **Проверка:** открыть публичную ссылку на видео → видео проигрывается, перемотка работает.

### 1.3 Обрезанная плавающая панель действий в публичных вьюверах (задача 3)
- **Новый компонент** `components/public/PublicViewerActions.tsx` — панель в стиле `.lb-actions`.
  Состав (без авторизации): **Скачать**, **Копировать в буфер** (только фото), **Копировать ссылку** (URL текущей публичной страницы), **Закрыть**.
- **Подключение:** встроенный вьювер в `PublicFolderPage`/`PublicAlbumPage` и карточка/вьювер `PublicViewPage`.
- **Проверка:** во всех трёх публичных вьюверах единая панель с урезанным набором действий.

## Группа 2 — Галерея «Видео»: разбивка по датам (задача 4)

- `pages/VideosPage.tsx`: применить существующий `groupByDate(videos)` из `lib/format` (как в `PhotosPage`),
  рендерить секции `.date-group`/`.date-head` с гридом `.vid-grid` внутри каждой.
  Featured-карточка последнего видео и стат-полоса — сохраняются сверху. Индексы для `Lightbox`
  считаются по плоскому массиву `videos` (как сейчас).
- **Проверка:** в «Видео» появляются заголовки дат, идентично «Фото».

## Группа 3 — Таб «Файлы»

### 3.1 Совместный скролл смарт-папок и списка (задача 5)
- **CSS** `styles/pages.css`: сейчас `.files-main { overflow: hidden }` + `.files-list { flex: 1; overflow: auto }`
  — скроллится только список, смарт-папки и крошки статичны. Сделать скролл-контейнером `.files-main`
  (`overflow-y: auto`), у `.files-list` убрать собственный скролл (`overflow: visible; flex: none`).
  Крошки `.files-bar` сделать `position: sticky; top: 0`, чтобы навигация не уезжала.
- **Проверка:** при скролле блок смарт-папок уезжает вверх вместе со списком файлов.

### 3.2 Превью фото/видео в строках списка файлов (задача 6)
- `pages/FilesPage.tsx`, `FileRow`: для `media.kind === 'photo' | 'video'` с наличием превью рендерить
  `MediaThumb` в ячейке имени вместо плашки `file-icon` (как уже делает `Inspector`). Небольшой бейдж видео — опционально.
  Минимальный CSS для фикс-размера превью-ячейки.
- **Проверка:** в табличном списке «Файлов» у фото/видео видно миниатюру.

## Группа 4 — Общий доступ: превью обложки публичного альбома (задача 7, backend)

Превью альбома сейчас не приходит с бэкенда вовсе (в `AlbumShareInfo` нет поля обложки),
поэтому фронт показывает иконку. Фронт (`LinkCard`) уже умеет рисовать `link.previewUrl` —
изменения только на сервере.

- **Proto** `Shared/BarkCloud.Proto/files_api.proto`, `message AlbumShareInfo`:
  добавить `string cover_preview_url = 7;`.
- **Files** `Features/Cloud/ListMyAlbumShares/ListMyAlbumSharesCommandHandler.cs`:
  подтянуть обложки альбомов страницы (через `AlbumViewBuilder`/storage) и проставить `CoverPreviewUrl`
  на каждый `AlbumShareInfo`. (Опц. то же в `CreateAlbumShareCommandHandler.ToGrpc`, чтобы свежая ссылка несла превью.)
- **Web** `Endpoints/CloudApiEndpoints.cs`, `AlbumShareJson`: добавить `previewUrl = s.CoverPreviewUrl`.
- **Frontend:** изменений не требуется.
- **Сборка:** regen proto → BarkCloud.Files → BarkCloud.Web.
- **Проверка:** в «Мои публичные» у публичного альбома отображается обложка.

## Порядок реализации (от низкого риска к высокому)

1. **Группа 2** — Видео по датам (чистый фронт).
2. **Группа 3** — Файлы: скролл (CSS) + превью в списке (фронт).
3. **Группа 1** — Вьюверы: cookie-громкость + видео на `/v` + панель действий (фронт + микро-правка бэка `/s/{token}/info`).
4. **Группа 4** — Превью альбома (proto + Files + Web, пересборка стека).

После каждой задачи: сборка затронутого стека (`npm run build` для фронта; `dotnet build` для бэка), затем коммит без push.
