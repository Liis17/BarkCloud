# FolderIcons

Общий пак иконок для пользовательских папок BarkCloud. Пак не зависит от конкретного клиента: это плоские SVG и JSON-манифест, которые можно подключать в любом проекте.

## Состав

| Путь | Назначение |
|---|---|
| `svg/<key>.svg` | Иконка 24×24, штриховая: `fill="none"`, `stroke="currentColor"`, `stroke-width="2"`, скруглённые концы |
| `manifest.json` | Категории и иконки: `key`, русская подпись `label`, `category`, `keywords` для поиска, `source` (происхождение) |
| `LICENSE-lucide` | Лицензия ISC для иконок с `source: "lucide:<имя>"` |

Цвет глифа задаётся через `currentColor`, поэтому клиент сам выбирает контрастный цвет поверх подложки.

## Ключи — публичный контракт

`key` сохраняется на сервере (`CloudDirectory.IconKey`) и приходит всем клиентам в `DirectoryInfo.icon_key`.

- Ключи не переименовывай и не удаляй — только добавляй новые. Для замены рисунка меняй файл, сохраняя ключ.
- Формат ключа: `^[a-z0-9]+(-[a-z0-9]+)*$`, не длиннее 64 символов (так проверяет сервер).
- Клиент, которому ключ неизвестен (например, старая версия приложения), показывает обычную папку.

## Добавление иконки

1. Положи `svg/<key>.svg` в том же формате (viewBox `0 0 24 24`, только `currentColor`, без `<script>`, `<style>`, обработчиков `on*`, ссылок и `url(...)`).
2. Добавь запись в `manifest.json` с существующей категорией.
3. Запусти тесты веб-клиента: `cd Backend/BarkCloud.Web/ClientApp && npx vitest run src/lib/folderIcons.test.ts` — тест сверяет манифест с файлами и проверяет безопасность SVG.

## Как пак попадает в сборки

- Web: Vite подключает пак через alias `@folder-icons` (`Backend/BarkCloud.Web/ClientApp/vite.config.ts`) и встраивает SVG в бандл при каждой сборке. Изменение `FolderIcons/**` запускает CI веба (`.github/workflows/build-backend-web.yml`); Docker-сборка копирует пак в client-стадию (`Backend/BarkCloud.Web/Dockerfile`).
- Другие клиенты подключают `manifest.json` и `svg/` на этапе своей сборки тем же способом: читают файлы из корня репозитория, без копий внутри проекта.
