# Обзор серии планов: дубликаты, папки, шаринг, альбомы, избранное

> Создано в рамках задачи по достройке загрузки/шаринга. Планы исполняются последовательно: план → выполнение (коммит после каждой задачи) → финальный коммит плана → следующий план учитывает фактические изменения. iOS не собирается (хост Windows). Android **заморожен** — не трогаем (у него своя копия proto).

## Принятые продуктовые решения

1. **Дубликаты — независимые копии.** Серверный дедуп по SHA256 отключается: каждая загрузка = отдельный блоб и `file_id`. Индекс по хешу уже неуникальный. Минус (принят): одинаковый контент занимает место многократно.
2. **Папки по умолчанию — реальные, маршрутизация на сервере по флагу.** В «Файлах» появляются системные папки **«Фото»**, **«Видео»**, **«Другие документы»** (фото→Фото, видео→Видео, прочее→Другие документы). Папка **«Недавно загруженные» больше не создаётся** (станет смарт-папкой позже; существующие не трогаем). Маршрутизация по типу применяется **только когда целевая папка не указана** (вкладки Фото/Видео, общий аплоад в вебе/iOS). При загрузке в конкретную папку (перетаскивание в открытую папку в вебе, любая загрузка с Windows-диска) — кладём именно туда, без авто-распределения.
3. **Шаринг между пользователями — приватные гранты.** Новая сущность доступа владелец→получатель→файл + RPC. Получатель видит файл в «Общие → мне доступны» (от кого, когда); доступ только авторизованному адресату.
4. **Публичная страница просмотра — SPA-маршрут** вне `AppShell` (напр. `/v/:token`) + публичное исключение в auth-middleware. Та же страница используется и для приватных user-to-user ссылок (но требует авторизации + грант). Зритель/получатель: только просмотр и скачивание.

## Ключевой технический контракт (общий для всех планов)

- **`AttachFileRequest` += `bool route_by_media_kind`** (аддитивное изменение proto, не ломающее). `true` → сервер игнорирует `directory_id` и кладёт по типу в системную папку. `false`/нет → текущее поведение (`directory_id`, пусто = корень). Drive/Android никогда не выставляют флаг → не затронуты.
- **`AttachFile` сохраняет `returns(CloudEmpty)`** — НЕ меняем тип ответа, чтобы не ломать Drive/iOS/Android. Авто-переименование при коллизии имени происходит на сервере «тихо»; клиент видит финальное имя при перезагрузке листинга.
- **`CheckFileHashResponse` += `exists` + локация** (entry_id, name, directory_id, directory_name) — аддитивно. `CheckFileHash` становится **чистой** проверкой (без побочного `AddUploaderToFile`); используется для модалок «такой файл уже есть».
- **Системные папки помечаются `SystemKind`** (enum на `CloudDirectory` + миграция) — поиск/ensure по флагу, а не по имени → устойчивы к переименованию и не дублируются.

## Связки между задачами (почему порядок именно такой)

- Снятие дедупа (Plan 01) **попутно чинит копирование на Windows-диске**: копия получает новый `file_id`, инвариант one-entry-per-file в `AttachFile` больше не падает. Поэтому Plan 05 (Drive) — в основном верификация поверх Plan 01.
- Снятие дедупа + чистая `CheckFileHash` (Plan 01) — фундамент для модалок дубликатов в вебе (Plan 03) и iOS (Plan 06).
- Приватные гранты и данные публичной страницы (Plan 02) — фундамент для шаринг-UI в вебе (Plan 04).
- iOS-автозагрузка **уже** пропускает загруженное по серверному хешу (`BackupManager.classify`) — цель сохраняется, если `CheckFileHashes` продолжает отвечать `exists=true` после снятия дедупа (он продолжает — `FileHash`-строки пишутся per-blob).

## Роадмап планов

| План | Область | Содержание |
|------|---------|-----------|
| **01** | Backend Files (ядро) | Снятие дедупа · авто-переименование при коллизии имени · системные папки Фото/Видео/Другие документы + `route_by_media_kind` · чистый `CheckFileHash` + локация · фикс бага альбома · proto/web-прокси · тесты |
| **02** | Backend Files (шаринг) | Превью в ответе публичной ссылки · приватные гранты (FileGrant) + RPC `ShareWithUser`/`ListSharedWithMe`/`RevokeUserShare` · доступ получателя через TempFile · proto/web-прокси · чистка грантов в UserDeleted/TrashPurge |
| **03** | Веб-клиент (загрузка/меню) | Модалка дубликата (имя+папка, «грузить ещё раз?») · убрать «Недавно загруженные», авто-распределение через `route_by_media_kind` · ПКМ «Добавить в избранное» · починка ПКМ в альбомах (`AlbumDetail.tsx`) |
| **04** | Веб-клиент (шаринг UI) | Публичная SPA-страница просмотра `/v/:token` + «Скачать» · модалка «поделиться с пользователем» (поиск) · раздел «Общие → мне доступны» |
| **05** | Windows Drive | Верификация дубликатов/копирования поверх Plan 01 · перестать молча глотать ошибки привязки в `Cleanup` |
| **06** | iOS (без сборки) | Модалка дубликата · разрешить дубликаты (снять `blockAlreadyUploaded`) · авто-распределение через `route_by_media_kind`, убрать «Недавно загруженные» · верификация автозагрузки-skip |

Детали — в `PLAN_01_…` и далее. Каждый план дополняется/уточняется по факту перед исполнением.
