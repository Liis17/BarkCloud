# Backend — Web

Parent: [[index]] · See also: [[api/identity-api]] · [[api/users-api]] · [[api/files-api]] · [[modules/shared-identity]] · [[modules/shared-auth]]

Дочерние: [[modules/web-system-updates]] — раздел «Обслуживание» (обновление/перезапуск бэкенда из настроек).

## Назначение

Веб-клиент BarkCloud: HTTP-сервер, который отдаёт браузеру **React-SPA** (собранный бандл из `wwwroot/`) и выступает gRPC-**клиентом** к микросервисам по docker-сети. Не gRPC-сервер — браузер общается с ним по HTTP/1.1, а наружу к Identity/Users/Files уходят gRPC-вызовы (h2c).

**Архитектура frontend:** одно React-SPA на TypeScript (исходники в `ClientApp/`, сборка Vite → `wwwroot/`). Переключение вкладок — client-side routing (`react-router-dom`), без перезагрузки страницы: каркас (Sidebar/Topbar/Footbar) остаётся смонтированным, меняется только контент (`<Outlet/>`). Данные грузятся через `/api`. Страницы **входа** (`/login`, `/register`, `/forgot`) остались **серверными** (`Login Page Full.html`, React+Babel inline).

Поток: нет валидного токена в cookie → редирект на серверный `/login`; валидный токен → SPA-маршрут (по умолчанию `/photos`). Каркас и настройки SPA получает через `/api/me` и `/api/settings/full` (раньше — серверные плейсхолдеры `{{ }}`).

## Расположение

`Backend/BarkCloud.Web/` (бэкенд) · `Backend/BarkCloud.Web/ClientApp/` (исходники React-SPA) · `Backend/BarkCloud.Web/wwwroot/` (собранный бандл, в git не хранится — пересобирается)

## Аутентификация

- Cookie: `bark_at` (access), `bark_rt` (refresh), `bark_did` (стабильный device-id). HttpOnly, SameSite=Lax.
- Токен валидируется **локально** по `JwtSettings:SecretKey/Issuer/Audience`. Эти значения web получает из **Configuration-сервиса** через `LoadConfiguration(ServiceId.Web)` — `JwtSettings` засеяны как общие (`ServiceId.Unknown`) и раздаются любому сервису, поэтому секрет автоматически совпадает с Identity.
- Истёк access → автоматический refresh через `IdentityApi.CreateToken`.
- Логин → `IdentityApi.Auth` (с device-заголовками `x-device-name`/`x-os-name`/`x-app-name`/`x-app-version`, base64). Поддержан 2FA-шаг.

## Вход по ключу безопасности (WebAuthn / FIDO2)

Web — тонкий релей к [[modules/backend-identity]] (валидация на сервере через `Fido2`; те же 4 метода переиспользуют Drive/Android/iOS). Хелпер `ClientApp/src/lib/webauthn.ts` (base64url↔ArrayBuffer, без внешних зависимостей; формат под `Fido2` raw response).

- **Вход** (passwordless, публичный, без токена): `POST /login/webauthn/begin {login}` → `{optionsJson, challengeId}`; `navigator.credentials.get` → `POST /login/webauthn/complete {challengeId, assertion, remember}` → cookie сессии (как `LoginAsync`). Кнопка «Войти ключом» на серверной странице логина (`Login Page Full.html`, vanilla JS, скрыта если `!window.PublicKeyCredential`). `AuthGateway.BeginWebAuthnAsync`/`CompleteWebAuthnAsync`.
- **Привязка/управление** (под токеном): `/api/settings/security/webauthn` (GET список), `…/register/begin`, `…/register/complete`, `…/remove` — проксируют в Identity. Карточка «Ключи безопасности» в `SettingsPage.tsx` (SecurityTab), `navigator.credentials.create`.
- Username-first; пароль + Email-OTP остаются как fallback.

## Регистрация (с подтверждением кодом по почте)

> **Режим без почты** (`Features:EmailEnabled=false`, см. [[modules/backend-configuration]]): Web читает флаг через `IConfiguration.EmailEnabled()`. Тогда `RegistrationGateway.BeginAsync` после `CreateAccount` (Identity сразу отдаёт `refresh_token`) выполняет общий хвост `CompleteAsync` (`CreateToken → SetPassword → IssueSession`) и возвращает `Success` — **без экрана ввода кода**. Маршруты `/forgot` и `/forgot/confirm` редиректят на `/login`. В страницу логина и в `/api/settings/full` (`system.emailEnabled`) прокинуты флаги `email.enabled`/`emailEnabled`: на логине скрыта ссылка «Забыли?», в «Обслуживании» — пометка по Notification.

В BarkCloud **есть** сервис уведомлений [[modules/backend-notification]] (паритет с BarkFluff), поэтому Web использует штатный клиентский email-флоу `IdentityApi` — тот же, что и мобильные клиенты. Двухшаговый процесс (`Auth/RegistrationGateway.cs`):

**Шаг 1 — `BeginAsync` (POST `/register`):**
1. `UsersServerApi.CheckExistUsername` / `CheckExistEmail` — проверка занятости.
2. `IdentityApi.CreateAccount(first/last/username/email)` с device-метаданными → Identity создаёт черновик, шлёт письмо `ConfirmationRegistration` с 6-значным кодом, возвращает `code_id`.
3. Рендер экрана ввода кода (`flash.kind=register_confirm`); `code_id` и пароль несутся в скрытых полях формы (как в 2FA-шаге).

**Шаг 2 — `ConfirmAsync` (POST `/register/confirm`):**
1. `IdentityApi.ConfirmAccount(code_id, code)` → `refresh_token` (Identity шлёт `SuccessfulRegistration`).
2. `IdentityApi.CreateToken(refresh)` → `access_token` (ConfirmAccount отдаёт только refresh).
3. `IdentityApi.SetPassword(password, old="")` с access-токеном. Для нового пользователя это первая установка пароля → письмо `PasswordChanged` **не** шлётся.
4. `AuthGateway.IssueSession` ставит cookie → редирект на `/photos`.

> Раньше регистрация шла в обход почты через серверные API (`AddDraftUser → ConfirmUser → ForceSetPasswordServer → CreateSessionForUserServer`) — это не спрашивало код и ошибочно слало письмо «Пароль изменён администратором» (`ForceSetPasswordServer`). Заменено на клиентский флоу выше; серверный `IdentityServerApi`-клиент в Web больше не используется.

## Восстановление пароля «Забыли пароль?» (код по почте)

Двухшаговый флоу через клиентский `IdentityApi` (`Auth/PasswordResetGateway.cs`); ссылки «Забыли?» на странице логина ведут на `/forgot`.

**Шаг 1 — `BeginAsync` (POST `/forgot`):** `IdentityApi.ResetPassword(email|username, OtpTypeId.Email)` с device-метаданными → письмо `ResetPassword` с кодом, `reset_id`. Identity анти-энумерационно отдаёт dummy `reset_id` даже для несуществующего пользователя → всегда показываем экран ввода кода (`flash.kind=forgot_confirm`).

**Шаг 2 — `ConfirmAsync` (POST `/forgot/confirm`):** `IdentityApi.ConfirmResetPassword(reset_id, code)` → access+refresh (Identity очищает старый хеш пароля) → `IdentityApi.SetPassword(newPassword, old="")` (старый пароль не нужен — хеш очищен) → `AuthGateway.IssueSession` → `/photos`. Новый пароль вводится на шаге 2; `reset_id` несётся в скрытом поле.

## Файлы

### Корень
- `Program.cs` — `LoadConfiguration(ServiceId.Web)`, DI gRPC-клиентов (Identity/Users/Files/Cloud/**Album** + серверные `UsersServerApi`/`FilesServerApi` с `JwtClientInterceptor` — для проверки занятости и аватара), `AddHttpClient("files-upload")` для прокси-загрузки, лимиты тела запроса 512 МБ (Kestrel + `FormOptions`), регистрация сервисов (+ `AuthGateway`, `RegistrationGateway`, `PasswordResetGateway`, `AdminGate`, `DockerService`), `MapWebEndpoints` + `MapCloudApiEndpoints` + `MapSystemEndpoints` + `MapSettingsEndpoints`, включение h2c. **`UseStaticFiles()`** отдаёт бандл SPA из `wwwroot/`. **`MapFallback`** — SPA-fallback: любой неизвестный путь (кроме `/api/*`) проверяет cookie (`AuthGateway.AuthenticateAsync`, заодно refresh) → не авторизован → редирект `/login`; иначе отдаёт `wwwroot/index.html`.
- `WebEndpoints.cs` — только серверные маршруты: `/` (редирект на `/photos` или `/login`), блок логина (`/login` GET/POST, `/logout`, `/register` GET/POST, `/register/confirm` POST, `/forgot` GET/POST, `/forgot/confirm` POST) + `LoginVars/RegisterVars/...`. **`GET /s/{token}`** — анонимный публичный резолв ссылки: `FilesServerApi.ResolveShare(token)` сервисным токеном → `found` ? `Results.Redirect(download_url)` (302) : `404`; `RpcException` → 404. Маршрут замаплен до `MapFallback`, чтобы не попасть под SPA-fallback. Маршруты приложения (`/photos`, `/videos`, `/albums`, `/files`, `/favorites`, `/trash`, `/settings`, `/shared`) отдаёт SPA через `MapFallback`; прежние page-эндпоинты, `ServePage`, `/shared.jsx`, `/shared.css` **удалены**.
- `Endpoints/CloudApiEndpoints.cs` — группа `/api/*` для Фото/Видео/Файлов (см. раздел «Фото/Видео/Файлы») + **`GET /api/me`** (каркас: профиль/аватар/хранилище/версия/хост — собирает `PageDataBuilder.BuildShellAsync`) + **`GET /api/storage`** (лёгкий рефетч только блока хранилища — `PageDataBuilder.BuildStorageAsync`, `GetUser` дёргается лишь при отсутствии лимита в Files; SPA вызывает при каждой смене вкладки). Также: `GET /api/cloud/path?entry=|dir=` (`GetPath` → `{ segments[{id,name}], fullPath }`, для «Показать в папке»), `POST /api/cloud/video/thumbnail` (`SetVideoThumbnail`, замена обложки видео), `POST /api/files/check-hash` (`CheckFileHash` → `{ fileId, exists, locations[] }` без побочных эффектов; для модалки дубликата «файл уже есть» — серверный дедуп снят). **Воспоминания**: `GET /api/cloud/memories?month=&day=&perYear=` (`GetMemories` → `{ groups }`, маппер `CloudJson.MemoryGroup`). (Вкладка «Карта» удалена; HTTP-эндпоинт `/api/cloud/map` и маппер `CloudJson.MapPoint` тоже убраны. gRPC-метод `CloudApi.ListMediaLocations` сервиса Files **остаётся** как часть контракта Files API — веб его больше не вызывает.)
- `SystemEndpoints.cs` — `/healthz` + группа `/api/system/*` (обновление/перезапуск бэкенда). См. [[modules/web-system-updates]].
- `SettingsEndpoints.cs` — группа `/api/settings/*` для действий страницы настроек (см. раздел «Настройки») + **`GET /api/settings/full`** (полное состояние страницы настроек — `PageDataBuilder.BuildSettingsJsonAsync`).

### Auth
- `AuthGateway.cs` — cookie, локальная валидация JWT, refresh, логин/логаут, `IssueSession` (общая выдача cookie сессии), `ClearSession` (удаление cookie без обращения в Identity — после удаления аккаунта).
- `AdminGate.cs` — гейт админ-действий по паролю `App:AdminPassword` (cookie `bark_admin`, HMAC на `JwtSettings:SecretKey`). См. [[modules/web-system-updates]].
- `RegistrationGateway.cs` — регистрация с кодом по почте через клиентский `IdentityApi` (`BeginAsync`/`ConfirmAsync`, см. раздел «Регистрация»).
- `PasswordResetGateway.cs` — восстановление пароля «Забыли пароль?» через клиентский `IdentityApi` (`BeginAsync`/`ConfirmAsync`, см. раздел «Восстановление пароля»).
- `WebUser.cs` — модель пользователя + `LoginOutcome`/`LoginResult` + `RegistrationOutcome`/`RegistrationResult` + `PasswordResetOutcome`/`PasswordResetResult`.

### Infrastructure
- `TemplateRenderer.cs` — рендер плейсхолдеров `{{ }}` / `{{{ }}}` / `| default("…")` с JS-экранированием. Используется только для серверной страницы логина.
- `DeviceInfo.cs`, `BrowserContext.cs` — построение device-метаданных из запроса браузера.
- `ServiceToken.cs` — генерация сервисного JWT (`TokenType=Service`) из общего `JwtSettings:SecretKey`.
- `DockerService.cs` — управление контейнерами бэкенда через `docker.sock` (pull/up/restart/start/stop, self-update веба через helper-контейнер). См. [[modules/web-system-updates]].

### Rendering
- `PageService.cs` — чтение и рендер файлов из `Pages/` (теперь только `Login Page Full.html`).
- `PageDataBuilder.cs` — сбор серверных данных, отдаётся клиенту как JSON: каркас `BuildShellAsync` (`Users.GetUser` + `Files.GetUserStorageInfo`) → `GET /api/me`; `BuildSettingsJsonAsync` (профиль + bio + email через `UsersServerApi.GetUserContacts`, флаги 2FA `ListOtpVerification`, приватность `GetPrivacySettings`, сессии с `deviceId`, storage) → `GET /api/settings/full`. Блок `storage.disk` (поля `totalAvailableStorage/diskUsedStorage/s3UsedStorage` из `GetUserStorageInfo`) питает **сегментированный бар физического диска сервера** в `StorageTab`: тёмно-серый — не-S3 данные, коричневый `#9A4F1E` — S3/облако, светло-серый — свободно.
- `CloudJson.cs` — единый маппинг gRPC-типов Files → JSON-карточки (`Media`/`Dir`/`Album`/`Entry`/`Trash`), общий для `/api`. `Media` отдаёт `previews[]` (128/512/1024 с URL) для `srcset`; `Trash` добавляет `deletedAt`/`purgeAt`.
- `Format.cs`, `FileKind.cs` — форматирование размеров/дат и классификация файлов.

### Pages (серверный логин)
- `Login Page Full.html` — единственная серверная страница (React+Babel inline через CDN, самодостаточна, не зависит от SPA). Многорежимная по `flash.kind`: `register` (`RegisterCard`, POST `/register`), `register_confirm` (`RegisterConfirmCard`, ввод кода, POST `/register/confirm`), `forgot` (`ForgotCard`, POST `/forgot`), `forgot_confirm` (`ForgotConfirmCard`, код + новый пароль, POST `/forgot/confirm`). Шаги подтверждения переиспользуют `OtpRow` и несут `code_id`/`reset_id`/пароль в скрытых полях. Сервер заполняет `{{ … }}` через `TemplateRenderer`.

### Frontend (React-SPA, `ClientApp/`)
- **Стек:** Vite + React 18 + TypeScript + `react-router-dom` v6. Сборка `npm run build` (`tsc --noEmit && vite build`) → `wwwroot/`. Dev: `npm run dev` (Vite на 5173, proxy `/api`,`/login`,… → `http://localhost:5148`).
- **Роутинг** (`src/main.tsx`): `BrowserRouter` → layout-route `AppShell` + вложенные маршруты `photos`/`videos`/`albums`/`files`/`favorites`/`trash`/`shared`/`settings` (`index` → `/photos`). Навигация в `Sidebar` через `NavLink` — без перезагрузки; меняется только `<Outlet/>`. `AppShell` при смене `pathname` рефетчит `GET /api/storage` и патчит `shell.storage` (первое срабатывание пропускается — storage только что пришёл из `/api/me`).
- **Альбомы** (`pages/AlbumsPage.tsx`, маршрут `/albums`, пункт «Альбомы» в Sidebar): отдельная вкладка — грид `AlbumCard` + `AlbumDetail` + создание (`AlbumFormModal`). Вкладки «Альбомы» внутри Фото/Видео **убраны**. Кандидаты для `PickMediaModal` грузятся лениво при первом открытии альбома: последние 100 фото + 100 видео из `cloud/media`.
- **Музыка** (`pages/MusicPage.tsx`, маршрут `/music`, пункт «Музыка» в Sidebar): список аудиотреков из облака через `/api/music/tracks` с автодогрузкой по скроллу (`IntersectionObserver`, без кнопки «Показать ещё»), глобальный миниплеер `AudioPlayerProvider`/`MiniPlayer` с отдельной от видео громкостью в cookie `bark_audio_vol`, shuffle/prev/next и same-origin потоком `/api/music/track/stream/{fileId}` (Web проксирует temp-URL из Files, включая `Range`, чтобы Web Audio не упирался в CORS). Миниплеер поддерживает 5-полосный Web Audio эквалайзер (60/250/1K/4K/12K), пресеты и сохранение настроек в `localStorage.bark_audio_eq`. `AudioPlayerProvider` публикует текущий трек в Media Session API: title/artist/album, обложки `coverUrl`/`largeCoverUrl`, playback state, position state и системные действия play/pause/prev/next/seek. Нулевая/ещё не извлечённая длительность в списках показывается прочерком, а не ложным `0:00` (старые аудио заполняет `LegacyMetadataBackfillService` в Files). При открытии видео в `Lightbox` активный трек миниплеера ставится на паузу и возобновляется после закрытия видео. У треков есть контекстное меню: добавление в плейлист, свойства, публичная ссылка (`/m/{token}` для аудио), переименование первой живой записи в папке, переход в папку и удаление файла в корзину. Плейлисты (`/api/music/playlists*`) отображаются плиткой как альбомы, поддерживают ручной порядок треков, добавление из списка треков, кастомные обложки из фото-облака или загрузкой новой картинки, публичные ссылки и приватный шаринг с пользователем; контекстное меню плейлиста даёт открыть, продублировать, сменить обложку, поделиться и удалить плейлист.
- **Воспоминания** (`components/memories/MemoriesStrip.tsx`): горизонтальная лента «В этот день» на вкладке «Фото» (`PhotosPage`), грузит `/api/cloud/memories`, скрывается если пусто; клик по году → `Lightbox` со снимками группы (+ панель действий через optional проп `actions`). Проп `refreshKey` — перезагрузка групп: `PhotosPage` инкрементит его при одиночном и массовом удалении фото, чтобы удалённый снимок исчез из ленты (сервер не кэширует — достаточно refetch). Стили `.memories`/`.mem-*` в `styles/shared.css`.
- **Каркас** (`src/components/shell/`): `AppShell` (грузит `/api/me`, держит контексты `ShellContext`/`PageHeaderContext`), `Sidebar`/`Topbar`/`Footbar`. Страницы задают заголовок Topbar через `usePageHeader`. Browser title/favicon управляются через `DocumentHeadProvider`/`useDocumentHead`: базово показывается активная вкладка SPA и брендовый favicon `barkcloud-icon-brand-b.png`, при открытом файле/Lightbox — имя и закруглённое превью файла, при открытом альбоме — имя и закруглённая обложка; внешние preview URL сначала проходят через same-origin `/api/head/icon`, чтобы canvas мог гарантированно скруглить изображение без CORS-ограничений; публичные `/v/*`, `/f/*`, `/al/*` задают title/favicon самостоятельно, так как идут вне `AppShell`.
- **Общие компоненты** (`src/components/`): `Icon`, `MediaThumb` (srcset+sizes), `Lightbox` (оригинал через `/api/files/download`; при переданном пропе `actions` — **плавающая панель действий** `.lb-actions` под изображением: поделиться (мини-меню: публичная/временная ссылка/пользователю), добавить в альбом (меню альбомов), показать в папке, скачать оригинал, скопировать изображение в буфер (только фото: fetch через same-origin прокси `GET /api/files/image?url=` → canvas → PNG → `ClipboardItem`; прямой fetch к Files невозможен — нет CORS, tainted-canvas. Прокси анонимный, тянет байты с внутреннего Files `/download/{id}` по GUID из URL, без SSRF; используется и кнопкой копирования на публичных страницах шаринга), свойства, удалить; иконки с title-тултипами; при удалении/опустении items индекс клампится/вьювер закрывается; без `actions` — прежняя кнопка «Скачать оригинал». `actions` = `useMediaActions().api` (`MediaActionsApi`) — модалки подтверждения/свойств/шаринга рендерятся в overlay родителя, `.modal-backdrop` поднят до z-index 1150 (выше `.lightbox` 1100). Панель подключена на Фото/Видео, в `DynamicFolderDetail`, `MemoriesStrip`, результатах поиска (`MediaSearchResults`), Избранном и `AlbumDetail`; без панели остаётся только Lightbox в `FilesPage` (инспектор)), `Modal`/`EmptyState`/`Loading`/`ContextMenu`/`RenameModal`/`ConfirmModal`/`PropertiesModal`/`SelectionBar` (плавающая панель групповых действий), альбомы (`AlbumCard`/`AlbumFormModal`/`PickMediaModal`/`AlbumDetail`). `components/public/PublicShareShell.tsx` — общий брендированный каркас публичных `/v/*`, `/m/*`, `/f/*`, `/al/*`, `/mpl/*`: topbar BarkCloud, hero-заголовок (`PublicShareHeader`: опциональные `label`/`subtitle`, `coverUrl` — превью обложки в иконке hero), loading/not-found состояния. **Публичные страницы следуют теме приложения** (светлая/тёмная): весь `.public-*` CSS на `var(--md-*)`, `data-theme` на `:root` применяется и вне `AppShell`. Страница альбома `/al` показывает обложку (первое медиа) в hero без eyebrow-подписи; `/v` не дублирует имя/размер/«Скачать» (блок `.public-file-summary` убран).
- **Хуки** (`src/hooks/`): `useToast`, `useContextMenu`, `useInfiniteMedia` (cursor-пагинация + IntersectionObserver), `useAlbumMembership`, `useMediaActions`, `useShell`, `usePageHeader`, `useFileDrop` (drag&drop загрузка, depth-counter), `useSelection` (множественный выбор по id), `useBulkMedia` (групповые действия галерей: удалить/в альбом/копировать ссылки), `useUploadManager` (глобальный менеджер загрузок — см. раздел «Загрузка файлов»).
- **data-слой** (`src/lib/api.ts`): `api`/`apiGet`/`apiPost`/`pickFiles`/`uploadFile`, `ApiError`; 401 → `window.location='/login'`. `checkDuplicate` считает SHA-256 (`crypto.subtle`) и спрашивает `/api/files/check-hash` → `{exists, locations}`. `uploadFile` всегда заливает новый блоб (серверный дедуп снят). Web-прокси `/api/files/upload` перед `FilesApi.GetUploadUrl` добавляет browser/device metadata (`x-device-name` и соседние заголовки), поэтому свойства файла показывают устройство загрузки и для веб-загрузок. Типы — `src/lib/types.ts`; форматирование — `src/lib/format.ts`; тема — `src/lib/theme.ts`.
- **Стили:** `src/styles/shared.css` (перенос прежнего shared.css, палитра Material 3 + тёмная `:root[data-theme="dark"]`) + `src/styles/pages.css` (page-specific). Импортируются один раз в `main.tsx`.
- **Тема** (light/dark/auto): bootstrap-скрипт в `<head>` `ClientApp/index.html` до рендера читает `localStorage.bark_theme` → `data-theme` (без мигания). Выбор — вкладка «Внешний вид» (`lib/theme.ts`, локально, без бэкенда).

## Фото / Видео / Файлы (данные и /api)

Маршруты SPA `/photos`, `/videos`, `/files` при монтировании грузят данные через `fetch('/api/…')`,
все действия (загрузка, создание/редактирование альбомов и папок, навигация) тоже идут через `/api`.
Эндпоинты — `Endpoints/CloudApiEndpoints.cs` (группа `/api`), паттерн как у `/api/settings/*`: `AuthGateway.AuthenticateAsync`
→ gRPC с пользовательским токеном (`BrowserContext.UserToken`); доменные ошибки (`FailedPrecondition` + `x-error-code`) → `400 { error, code }`.

- Каркас (CloudApi): `GET me` — данные Sidebar/Topbar/Footbar (профиль/аватар/хранилище/версия/хост) для `AppShell` SPA.
- Каталоги (CloudApi): `GET cloud/list?dir=`, `POST cloud/dir`/`dir/rename`/`dir/move`/`dir/delete`, `POST cloud/attach`, `POST cloud/entry/rename`/`entry/move`/`entry/delete` (удаление файла/папки = перемещение в корзину), `POST cloud/entries/delete { entryIds }` (чанки по 100 в `CloudApi.DeleteFileEntries`).
- Корзина (CloudApi): `GET cloud/trash?limit=&cursorAt=&cursorId=` (`ListTrash`), `POST cloud/trash/restore`/`trash/purge` (по `entryId`), `POST cloud/trash/restore-batch`/`trash/purge-batch` (массив `entryIds`, Web последовательно вызывает gRPC и возвращает batch-summary), `POST cloud/trash/empty`.
- Галерея (CloudApi): `GET cloud/media?kind=photo|video&limit=&cursorAt=&cursorId=` (`ListUserMedia`, cursor-пагинация), `POST cloud/media/delete { fileId }` (`DeleteUserMedia`), `POST cloud/media/delete-batch { fileIds }` (Web batch-wrapper для массового удаления галерей). Карточка галереи (`CloudJson.MediaItem`) несёт `entryIds`/`entryNames`/`entriesCount` (поле `UserImageItem.entry_ids` в proto) — нужны контекстному меню для переименования/перехода в папку через `entry/rename`·`GetPath`; удаление галерейных карточек всегда идёт по `fileId` и помещает медиа в корзину, включая медиа без записи каталога.
- Избранное (CloudApi): `GET cloud/favorites?limit=&cursorAt=&cursorId=` (`ListFavorites`, карточки `CloudJson.Media`), `POST cloud/favorites/add`/`cloud/favorites/remove` (по `fileId`, идемпотентно). Питает страницу `/favorites`; добавление/снятие — для будущего контекстного меню (и кнопки-звезды на самой странице).
- Альбомы (AlbumApi): `GET albums`, `GET albums/items?album=&kind=`, `POST albums`/`albums/update`/`albums/delete`/`albums/items/add`/`albums/items/remove`.
- Публичные ссылки (CloudApi): `GET shares` (`ListMyShares`), `POST shares` `{fileId, name}` (`CreateShare`), `POST shares/revoke` `{shareId}` (`RevokeShare`, POST т.к. в `api.ts` нет `apiDelete`). Дружелюбный `url = {origin}/v/{token}` (просмотр) / `{origin}/s/{token}` (скачивание) собирается через `ResolveOrigin`: если задан `App:PublicHost` (env `WEB_PUBLIC_HOST`, напр. `https://storage.fooxboy.net:24565`) — берётся `scheme://authority` из него (включая порт); иначе fallback на `http.Request.Scheme + http.Request.Host`. Аналогично для папок (`FolderShareJson`, `/f/{token}`) и альбомов (`AlbumShareJson`, `/al/{token}`). Питает страницу `/shared`.
- Свойства файла: `GET files/info?id=` → серверный `FilesServerApi.GetFileData` (авторизуется сервисным токеном через интерцептор; эндпоинт сам проверяет владение — id пользователя ∈ `uploaders`, иначе 403). Полная карточка `UploadFileInfo` (+ etag) для модалки «Свойства». Дополнительно подтягивает EXIF/ffprobe/PDF/Office-метаданные через клиентский `FilesApi.GetFileMetadata` (юзер-токен) и кладёт их под полем `metadata`. `GET files/activity?id=&limit=` → `CloudApi.ListFileActivity`, последние действия по файлу для секции «История». Если метаданных нет (бэкафилл ещё не прошёл или нечего извлекать) — `metadata` отсутствует, модалка просто не показывает секцию.
- Файлы (FilesApi): `POST files/upload` — **прокси-загрузка**: `GetUploadUrl` → стрим байтов `HttpClient`-ом на **внутренний HTTP1-эндпоинт** Files `FilesService:Http1Base` (= хост из `FilesService:Host` + порт `FILES_HTTP1PORT`, по умолч. `7026`) `/upload/{fileId}` — минуя nginx/TLS и `ExternalEndpoint:Host`; публичный `upload.Url` — fallback. Возвращает `fileId`. `GET files/download?ids=` — временные ссылки на оригинал(ы) через `GetTempDownloadUrl`. **`GET files/view?id=`** — inline-просмотр оригинала same-origin: web получает temp-URL, качает содержимое с внутреннего `FilesService:Http1Base`/`download/{tempId}` (как upload-прокси) и стримит без `Content-Disposition: attachment`, чтобы браузер **открыл** текст/код во вкладке (скачивание Files всегда `attachment`, CORS на files нет — прямой fetch/новая вкладка по temp-URL скачали бы файл). Используется двойным кликом в «Файлах» для текстовых форматов. `POST files/check-hash` (`CheckFileHash`) — проверка наличия по SHA-256 без побочных эффектов: `{exists, locations}`; при совпадении клиент показывает модалку дубликата (грузить копию или нет). Серверный дедуп снят.
- Путь и обложка видео (CloudApi): `GET cloud/path?entry=|dir=` (`GetPath`) — хлебные крошки/«Показать в папке»; `POST cloud/video/thumbnail` (`SetVideoThumbnail`, `{videoFileId, imageFileId}`) — заменить обложку видео загруженным кадром.

UI: в сетке — превью (`MediaThumb`: `<img srcset sizes>` поверх MD3-иконки-плейсхолдера по типу медиа, проявляется по `onLoad`). Галереи `/photos`·`/videos` грузятся бесконечной прокруткой (`useInfiniteMedia` + `IntersectionObserver`, cursor-пагинация); **обе** группируются по датам через `groupByDate` (секции `.date-group`/`.date-head`). В табличном списке `/files` строки фото/видео показывают `MediaThumb` (класс `.file-thumb`) вместо плашки-иконки; блок умных папок (`DynamicFoldersStrip`) скроллится вместе со списком — скролл-контейнер `.files-main`, крошки `.files-bar` липкие. При открытии — оригинал в `Lightbox`: листание (боковые кнопки/`←`/`→`), зум фото колесом + drag-pan, перемотка видео `←`/`→` на ±5 c.
Загрузка фото/видео на `/photos`·`/videos` идёт с `routeByMediaKind:true` — сервер сам кладёт по типу в системные папки «Фото»/«Видео»/«Другие документы»; клиентская папка «Недавно загруженные» больше не создаётся. Документы на `/files` привязываются к текущей открытой папке (без авто-распределения).

**Глобальный менеджер загрузок** (`useUploadManager`): React Context (`UploadManagerProvider`) в `AppShell`, переживает навигацию между вкладками. Страницы вызывают `enqueue(files, attachOptions)`, менеджер сам обрабатывает проверку дубликатов, загрузку через XHR (с прогрессом) и attach к каталогу. Параллельная загрузка до 4 файлов одновременно. Статус каждой задачи: `pending → checking → uploading → attaching → done | error | skipped`. Ошибки показывают причину + кнопку «Повторить». Дедупликация: `checkDuplicate` + модалка с решением для файла или всей партии (`skip/skip-all/upload/upload-all`). `UploadBanner` — sticky-баннер вверху контентной области с общим прогрессом; при нажатии раскрывается в список файлов с индивидуальными статусами. `beforeunload`-предупреждение при активных загрузках. Два контекста для производительности: `useUploadActions` (стабильный, для страниц — `enqueue`, `attachVersion`) и `useUploadState` (реактивный, для `UploadBanner` — `tasks`, `summary`, прогресс). Страницы подписаны на `attachVersion` через `useEffect` → перезагружают данные при завершении загрузки.
ПКМ по карточке (фото/видео/файл/папка) даёт контекстное меню (`ContextMenu`/`useMediaActions` в `ClientApp/src`): копировать ссылку (временная), **«Создать публичную ссылку»** (`lib/share.createShare` → `POST /api/shares` → постоянный `/s/{token}` в буфер; общий хелпер для `useMediaActions` и `FilesPage.fileMenu`), переименовать (`RenameModal`), удалить в корзину (`POST /api/cloud/media/delete`: живые записи каталога уходят в корзину, а для медиа без записей создаётся запись корзины), **«Добавить в избранное»** (`cloud/favorites/add`), **свойства** (`PropertiesModal` → `files/info` + `files/activity`; модалка раздельно показывает базовые поля, секцию «Метаданные» — EXIF/GPS/камера/выдержка-ISO для фото, длительность/кодеки/fps/битрейт для видео, автор/заголовок/страницы для документов — и секцию «История» с последними действиями; GPS-координаты как ссылка на openstreetmap.org. Для медиа с геоданными модалка показывает секцию «Место съёмки» — встроенную мини-карту OSM (`FileLocationMap`: `export/embed.html`-iframe с маркером, без JS-зависимостей; стиль `.prop-map`)), **«Показать в папке»** (`GetPath` → навигация на `/files` с раскрытым стеком и подсветкой записи через router-state), для фото/видео — добавить/удалить из альбома (submenu; членство считается клиентски через `ListAlbumItems`), для видео — **«Заменить превью»** (выбор изображения → `uploadFile` → `cloud/video/thumbnail`). Аватар пользователя в `sb-user` берётся из `user.avatar_url` (`PageDataBuilder.BuildShellAsync` → `ProfilePicturePreview`), с фоллбэком на инициалы. ПКМ по фото/видео **внутри альбома** (`AlbumDetail`) даёт узкое меню (`useContextMenu`): сделать обложкой, в избранное, публичная ссылка, свойства, убрать из альбома.

**Drag&drop загрузка** (`useFileDrop`): на `/photos`·`/videos`·`/files` перетаскивание файлов в окно подсвечивает зону (`.dropzone`/`.files-shell` + `.drop-overlay`) и запускает тот же `doUpload`. **Множественный выбор** (`useSelection` + `SelectionBar`): чекбоксы на карточках галерей (`.selbox`) и в таблицах файлов/корзины (колонка `.selcell` + «выбрать все» в шапке); плавающая панель даёт групповые действия — удалить в корзину по `fileId` (`cloud/media/delete-batch`) или `entryId` (`cloud/entries/delete` → `CloudApi.DeleteFileEntries`), копировать ссылки (галереи и файлы), добавить в альбом (только галереи, `useBulkMedia`), **переместить в папку** (только «Файлы»: `MoveToFolderModal` навигирует дерево через `cloud/list`, цикл `cloud/entry/move`). Batch-ответ Web имеет форму `{ total, succeeded, failed, invalidIds?, succeededIds?, failedIds? }`; для `cloud/entries/delete` доступен счётчик, потому что gRPC-команда сама молча пропускает чужие/несуществующие записи. **Shift-выделение диапазона**: `useSelection` держит якорь (последний отмеченный) и `select(id, orderedIds, shift)` тянет диапазон в порядке отображения; selbox галерей и чекбокс строки файлов прокидывают `e.shiftKey` (в галереях порядок берётся из `useBulkMedia` по `items`). В корзине (`/trash`) — групповое **«Восстановить»** и **«Удалить навсегда»** (с `ConfirmModal`) через `trash/restore-batch`·`trash/purge-batch`. Hero-карточка последнего видео и папки в таблице из массового выбора исключены.
Альбомы общие для Фото и Видео (`ListAlbums`). Инспектор «Свойства» показывает EXIF/ffprobe/PDF/Office-метаданные и историю активности из Files API. Шаринг реализован — постоянные публичные ссылки (см. раздел «Общий доступ»).

## Общий доступ (публичные ссылки)

Маршрут SPA `/shared` (`pages/SharedPage.tsx`) — рабочая страница «Общий доступ» с вкладками **«Мои публичные»**, **«Я поделился»** и **«Мне доступны»** (прежний demo-макет с фейковой статистикой/людьми/вкладками удалён). **Все три вкладки грузятся параллельно при открытии страницы** (счётчики актуальны без кликов; lazy-загрузка по переключению убрана). **Пагинация «Показать ещё»** по курсорам: «Мои публичные» — источники `/api/shares`, `/api/folder-shares`, `/api/album-shares`, `/api/music/playlist-shares` (дозагружаются только источники с живым курсором, append + пересортировка по `createdAt`), «Я поделился» — `/api/shared/i-shared`, «Мне доступны» — `/api/shared/with-me` (`i-shared-folders`/`folders-with-me` курсоров не имеют — грузятся целиком); у счётчика вкладки `+`, пока есть следующая страница. «Мои публичные»: карточки ссылки (`LinkCard`: **превью файла/альбома/музыкального плейлиста** из `previewUrl` (фолбэк — иконка по `kind`), имя, URL, дата, счётчик переходов) с кнопками **«Скопировать»** (`navigator.clipboard`) и **«Отозвать»** (`window.confirm` → revoke endpoint по `kind`). Превью пришло из `ShareInfo.media_kind`/`preview_url` (proto): `ListMySharesCommandHandler` Files батчем подтягивает тип медиа и минимальное превью (target 128) — `ShareJson` отдаёт `mediaKind`/`previewUrl`. **«Я поделился»**: `GET /api/shared/i-shared` (`ListMyOutgoingSharesAll` + резолв получателей через `UsersServerApi`), карточки `ISharedCard` группируют гранты по файлу (`groupIShared`) и показывают чипы получателей с отзывом по получателю (`POST /api/shared/revoke-grant`). «Мне доступны»: `GET /api/shared/with-me` (`SharedCard`: превью/имя файла, «от кого», когда; кнопка «Скачать» → `POST /api/shared/download` → переход на temp-URL).

Выдать грант («Поделиться с пользователем», `ShareWithUserModal`) можно из контекстного меню файла в «Файлах», «Фото», «Видео» и внутри альбома.

**Шаринг папки с пользователем** (`/api/shared/grant-folder`/`revoke-folder-grant`/`i-shared-folders`/`folders-with-me`/`dir?dir=`): из `dirMenu` «Файлов» — «Поделиться с пользователем» (`ShareWithUserModal` с `folderId`). Во вкладке «Я поделился» секция «Папки, которыми я поделился» (`IFolderCard`, чипы получателей + отзыв); во «Мне доступны» — «Доступные мне папки» (`SharedFolderCard` → `SharedFolderModal`: навигация по поддереву через `/api/shared/dir`, просмотр фото/видео и скачивание).

Создаются ссылки из контекстного меню любого файла («Файлы», «Фото», «Видео», «Музыка») — `lib/share.createShare(fileId, name, toast)` шлёт `POST /api/shares` и кладёт в буфер ссылку на **страницу просмотра**: `/v/{token}` для обычных файлов/фото/видео и `/m/{token}` для аудиотреков (прямое скачивание — `/s/{token}`). Пункт **«Поделиться с пользователем»** (`ShareWithUserModal`) ищет получателей (`/api/shared/users/search`) и выдаёт приватный грант (`/api/shared/grant`).

**Публичные папки** (`/api/folder-shares` GET/POST + `/revoke`): `CreateFolderShare`/`ListMyFolderShares`/`RevokeFolderShare`. `FolderShareJson` собирает `url` через `ResolveOrigin` (см. выше), `kind=folder`. В «Мои публичные» вкладка `SharedPage` грузит и `/api/shares`, и `/api/folder-shares`, мержит (папки — `LinkCard` с иконкой папки; отзыв роутится по `kind`). Папку делают публичной из контекстного меню в «Файлах» (`dirMenu` → `createFolderShare`). **Публичная страница папки** `/f/:token` (`pages/PublicFolderPage.tsx`, вне `AppShell`, анонимна): `fetch GET /f/{token}/list?dir=` (`ResolveFolderShare` сервисным токеном) → брендированный `PublicShareShell`, hero BarkCloud, грид подпапок + файлов; навигация по подпапкам, клик по фото/видео — встроенный вьювер (img/video по temp-URL), по файлу — скачивание. Корневой контейнер страницы — собственный scroll-viewer (`height: 100vh; overflow-y: auto`), потому что глобальный shell держит `body` с `overflow: hidden`; overlay встроенного viewer тоже прокручиваемый. Fallback в `Program.cs` пускает `/f/*` без авторизации (как `/v/*`).

**Публичные альбомы** (`/api/album-shares` GET/POST + `/revoke`, на `CloudApi`): `CreateAlbumShare`/`ListMyAlbumShares`/`RevokeAlbumShare`. `AlbumShareJson` собирает `url` через `ResolveOrigin` (см. выше), `kind=album`, `previewUrl=cover_preview_url`. В «Мои публичные» вкладка `SharedPage` грузит и `/api/album-shares` (превью обложки из `previewUrl`, фолбэк — иконка фото; отзыв по `kind`). Обложку наполняет `ListMyAlbumSharesCommandHandler` в Files: грузит альбомы страницы и собирает их view через `AlbumViewBuilder` → `AlbumShareInfo.cover_preview_url` (proto-поле 7). Альбом делают публичным кнопкой «Поделиться» в `AlbumDetail` (`lib/share.createAlbumShare`). **Публичная страница альбома** `/al/:token` (`pages/PublicAlbumPage.tsx`, вне `AppShell`, анонимна): `fetch GET /al/{token}/list?cursor*` (`ResolveAlbumShare` сервисным токеном) → брендированный `PublicShareShell`, hero BarkCloud, грид элементов с пагинацией «Показать ещё», встроенный вьювер. Корневой контейнер страницы — собственный scroll-viewer (`height: 100vh; overflow-y: auto`), чтобы большие альбомы прокручивались при глобальном `body overflow: hidden`; overlay встроенного viewer тоже прокручиваемый. Fallback в `Program.cs` пускает `/al/*` без авторизации.

**Публичные музыкальные плейлисты** (`/api/music/playlist-shares` GET/POST + `/revoke`, на `MusicApi`): `CreatePlaylistShare`/`ListMyPlaylistShares`/`RevokePlaylistShare`. `MusicPlaylistShareJson` собирает `url=/mpl/{token}`, `kind=musicPlaylist`, `previewUrl=cover_preview_url`. Плейлист делают публичным из `MusicPage` (`lib/share.createMusicPlaylistShare`); приватный шаринг с пользователем идёт через `ShareWithUserModal` и `/api/music/shared/grant`. Получатель видит плейлисты в секции «Доступные мне» вкладки `/music` (`/api/music/shared/with-me`) и может слушать без редактирования порядка/обложки. **Публичная страница плейлиста** `/mpl/:token` (`pages/PublicMusicPlaylistPage.tsx`, вне `AppShell`, анонимна): `fetch GET /mpl/{token}/list` (`ResolveMusicPlaylistShare` сервисным токеном) → hero с обложкой, список треков и sticky-аудиоплеер; громкость хранится в `bark_audio_vol`, отдельно от видео `bark_vol`. Fallback в `Program.cs` пускает `/mpl/*` без авторизации.

**Публичные аудиотреки**: обычный `CreateShare` для файла с `mediaKind=audio` возвращает страницу `/m/{token}` (а не `/v/{token}`); прямое скачивание остаётся `/s/{token}`. **Публичная страница трека** `/m/:token` (`pages/PublicMusicTrackPage.tsx`, вне `AppShell`, анонимна): `fetch GET /s/{token}/info` (`ResolveShare` сервисным токеном) → hero с обложкой/именем, кнопка скачивания и встроенный `<audio controls>` по temp-URL оригинала. Fallback в `Program.cs` пускает `/m/*` без авторизации; старые `/v/{token}` для аудио в `PublicViewPage` перенаправляются на `/m/{token}`.

**Поиск по имени** (контекстный): поле в `Topbar`; на `/photos`·`/videos` Enter ведёт на текущую вкладку с `?q=`, на остальных — на `/files?q=`; input синхронизирован с текущим `?q`. `GET /api/cloud/search` принимает `kind=media|photo|video` (прокидывается в `SearchFilesRequest.kind_filter`, repeated MediaKind; фильтр в SQL до `Take(limit+1)` — limit/cursor честные). На Фото/Видео результаты рендерит `components/search/MediaSearchResults.tsx` (`kind=media`): сетка `photo-grid` с превью, Lightbox по клику, «Показать ещё» по курсору, баннер + «Очистить». `FilesPage` при наличии `q` грузит все типы списком вместо листинга папки (баннер «Результаты поиска» + «Очистить»; умные папки скрыты) + кнопка «Показать ещё» (cursor-пагинация).

**Публичная страница просмотра** `/v/:token` (`pages/PublicViewPage.tsx`, маршрут вне `AppShell`) — анонимная: `MapFallback` отдаёт `index.html` для `/v/*` без авторизации; страница `fetch`-ит `GET /s/{token}/info` (метаданные + публичное превью через `ResolveShare`) и показывает брендированный hero BarkCloud, превью фото/видео и кнопку «Скачать» (`/s/{token}` → 302). Для `mediaKind=audio` старые `/v/*` ссылки заменяются на `/m/*`. **Видео воспроизводится встроенным плеером** прямо на странице: `/s/{token}/info` дополнительно отдаёт `downloadUrl` (прямой temp-URL оригинала, тот же, что у редиректа `/s/{token}`), для `mediaKind=video` рендерится `<video src={downloadUrl} controls>` (без autoplay — у landing нет жеста). У публичных media-вьюверов (`/v`, `/f`, `/al`) есть обрезанная плавающая панель действий `components/public/PublicViewerActions.tsx` (стиль `.lb-actions`): скачать, копировать изображение (фото), копировать ссылку на страницу, закрыть (в оверлеях `/f`·`/al`) — без авторизованных действий. Громкость видео общая для всех плееров (облачный `Lightbox` + публичные) — хранится в cookie `bark_vol` через `lib/volume.ts` (`persistVolumeRef`). Корневой контейнер страницы прокручиваемый на случай, если карточка просмотра не помещается по высоте экрана. Приватный шаринг между пользователями — гранты `FileGrant` (см. [[api/files-api]]); получатель видит файлы во вкладке «Мне доступны».

**Сквозная цепочка:** Web `/api/shares*` → `CloudApi.{Create,ListMy,Revoke}Share` (user-токен); публичный `/s/{token}` (анонимный) → `FilesServerApi.ResolveShare` (сервисный токен). `ResolveShare` создаёт `TempFile` для оригинала (т.к. прямой `/download/{fileId}` для `UploadFileType.CloudFile` запрещён в `DownloadFileCommandHandler` — допустимы только аватарки и превью-блобы) и возвращает temp-URL; Web делает 302 на него. Записи ссылок живут в БД Files (сущность `ShareLink`, storage `ShareStorage`), см. [[api/files-api]] и [[modules/backend-files-cloud]].

`Program.cs` веба включает `UseForwardedHeaders(XForwardedProto | XForwardedHost)` с очищенными `KnownNetworks`/`KnownProxies` — за nginx Kestrel должен видеть исходный `scheme=https`. Если reverse-proxy не прокидывает порт в `Host`/`X-Forwarded-Host`, публичные ссылки теряют порт. Для корректной генерации ссылок нужно задать `WEB_PUBLIC_HOST` (env → `App:PublicHost`) полным URL включая порт (напр. `https://storage.fooxboy.net:24565`). Метод `ResolveOrigin` в `CloudApiEndpoints` читает его и использует как origin; при пустом значении — fallback на `http.Request`.

> **Семантика отзыва:** `RevokeShare` удаляет запись `ShareLink` — `ResolveShare` сразу начинает отдавать 404, и новые редиректы/temp-ссылки не создаются. Уже выданная temp-ссылка остаётся живой до истечения `TempFiles:ExpiresAt` (минуты) — это узкое окно, а не постоянная утечка.

## Настройки (рабочие параметры)

Маршрут SPA `/settings` (`pages/SettingsPage.tsx`) — настоящие вкладки (левая навигация `.set-nav`, активная секция в URL hash, рендерится только она). Данные грузятся на mount через `GET /api/settings/full` (раньше — серверный `page_data_json`). Вкладки: Аккаунт, Безопасность, Приватность, Хранилище, Устройства и сессии, Внешний вид, Обслуживание (только если задан `App:AdminPassword`).

Действия идут через REST `/api/settings/*` (`SettingsEndpoints.cs`) — паттерн как у `/api/system/*`: проверка `AuthGateway.AuthenticateAsync`, затем gRPC с токеном пользователя (`BrowserContext.UserToken`), ошибки маппятся в `BadRequest { message }`. Эндпоинты:

- Профиль (UsersApi): `POST profile/name`, `POST profile/bio`, `GET profile/username-available?u=`, `POST profile/username`.
- Приватность (UsersApi): `GET/POST privacy` (`UpdatePrivacySettings` целиком; 0=Всем,1=Контактам,2=Никому).
- Безопасность (IdentityApi): `POST security/password` (`old_password` обязателен — пароль уже задан), `GET security/2fa`, `POST security/2fa/enable` (→ qr+code), `…/confirm`, `…/disable`. Ключи безопасности: `GET security/webauthn`, `POST security/webauthn/register/begin`·`/register/complete`·`/remove` (см. «Вход по ключу безопасности»).
- Устройства/сессии (Identity+Users): `GET sessions`, `POST devices/rename`, `POST sessions/revoke` (один `RemoveActiveSession` — он сам удаляет устройство в Users; текущую сессию завершать запрещено), `POST sessions/revoke-others`.
- Аккаунт: `POST account/delete` (`DeleteAccount` + `ClearSession` → клиент уходит на `/login`).
- Аватар: `POST avatar` (multipart `file` → `FilesServerApi.UploadAvatarServer` → `UsersServerApi.SetProfilePictureServer`), `POST avatar/remove` (тот же server-API с пустыми URL).

Удалены секции-плейсхолдеры без бэкенда (уведомления, язык, API-интеграции, E2E, резервные коды, экспорт/деактивация).

## Ограничения / TODO

- Отзыв публичной ссылки (`/s/{token}`) даёт 404 сразу и новые редиректы не создаются, но уже выданная temp-ссылка живёт до истечения `TempFiles:ExpiresAt`. См. раздел «Общий доступ».
- Длительность видео не приходит из Files API — в карточках видео показываются только разрешение (по `image_width/height`) и размер.
- Превью/оригиналы грузит **браузер** по абсолютным URL `{ExternalEndpoint:Host}/web/download/{id}` — ключ Files `ExternalEndpoint:Host` обязан быть `https://cloud.barkfluff.com:7025` (со схемой **https**), иначе на https-странице превью — mixed-content и блокируются браузером. Загрузка байтов от этого ключа уже **не** зависит (идёт на внутренний `cloud-files:7026`).
- Аплоад большого файла: nginx-vhost фронта веб-клиента (`cloud.barkfluff.com:443` → cloud-web) должен иметь `client_max_body_size 512m;` (по умолчанию 1 МБ → `413`). Этот vhost — вне репозитория (`nginx/cloud.barkfluff.conf` покрывает только gRPC-порты 7020/7021/7025). На стороне .NET лимиты уже сняты в `Program.cs` (Kestrel `MaxRequestBodySize` + `FormOptions.MultipartBodyLengthLimit` = 512 МБ).
- Шаги с кодом (2FA-логин, подтверждение регистрации, сброс пароля) переносят логин/пароль/`code_id`/`reset_id` в скрытых полях формы — упрощение MVP, стоит заменить на короткоживущий pending-токен/серверное состояние.
