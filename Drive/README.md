# BarkCloud.Drive — облако как диск Windows

BarkCloud.Drive монтирует облачные файлы и папки как диск Dokany. В решении три проекта: `BarkCloud.Drive.Contracts` с IPC-контрактами, скрытый процесс `BarkCloud.Drive.Engine` с файловой системой и WPF-приложение `BarkCloud.Drive.App`.

## Требования и запуск

Нужен Windows и установленный Dokany 2.x. Движок подключается к BarkCloud по gRPC и HTTP. Адрес по умолчанию задаётся в `Drive/BarkCloud.Drive.Engine/appsettings.json`: `cloud.barkfluff.com`, Identity `7020`, Users `7021`, Files `7025`. Адреса и порты можно переопределить в настройках приложения. Для self-hosted сервера клиенту нужен доступ к `https://{Host}` на порту `443` для Upload 2.0; этот endpoint отдельный от `FilesPort` и `/web`.

Для локальной сборки и запуска:

```bash
dotnet build Drive/BarkCloud.Drive.slnx
dotnet run --project Drive/BarkCloud.Drive.App
```

При первом подключении приложение запускает Engine. После входа выберите букву диска и нажмите «Примонтировать».

## Сессия, TLS и IPC

Refresh-токен хранится в DPAPI для текущего пользователя Windows (`%LOCALAPPDATA%\BarkCloud.Drive\refresh.bin`); access-токен остаётся в памяти. При временном обрыве сети движок сохраняет сессию и повторяет восстановление с растущей паузой от 5 секунд до 5 минут. После восстановления он загружает профиль, запускает outbox и пытается вернуть последнее монтирование.

Сессия привязана к `ServerKey`: нормализованному HTTPS-адресу Identity и портам Files и Users. При несовпадении ключа сохранённый токен удаляется. Старый raw DPAPI refresh-токен без `ServerKey` при первом чтении привязывается к текущей конфигурации без проверки, тем ли сервером он выдан. Если конфигурацию сменили до обновления токена, он будет отправлен на новый сервер. «Выйти» останавливает повторы outbox, размонтирует диск и очищает локальную сессию и кеш; очередь outbox остаётся на диске для соответствующей учётной записи.

Проверка сертификата TLS строгая по умолчанию (`ServerConfig.AcceptAnyCert` и `DangerousAcceptAnyServerCert` выключены). В мастере первого запуска и настройках есть галочка «Принимать любые сертификаты сервера»; по умолчанию она выключена. Явное `AcceptAnyCert: true` в существующем `server.json` сохраняет прежнее поведение и разрешает самоподписанный или иной непроверенный сертификат; включайте эту опцию только для доверенного self-hosted-сервера.

UI и Engine общаются через named pipe `BarkCloud.Drive.Engine.<SID>` с `PipeOptions.CurrentUserOnly`. Pipe привязан к SID текущего пользователя Windows.

## Чтение и кеш

Открытие облачного файла не скачивает его целиком. `Engine` запрашивает по HTTP Range нужные блоки по 1 МиБ и кеширует их в настроенной папке. Если сервер не поддерживает Range, чтение переключается на скачивание всего файла.

Лимит кеша скачанных файлов — 5 ГиБ. Очистка раз в минуту удаляет старые файлы и старается уменьшить кеш до 80% лимита. Кандидаты моложе минуты пропускаются, а попытка удалить открытый файл завершается `IOException` и пропускается. Время LRU обновляется отдельно, не чаще раза примерно в 30 секунд; поэтому лимит мягкий, а порядок вытеснения приблизительный. Рабочие копии записи и outbox в этот кеш не входят. Список папки кешируется на 5 секунд; отдельного change-feed у клиента нет.

Во время долгой сетевой или дисковой операции внутри callback Dokany движок раз в 10 секунд продлевает таймаут через `DokanKeepAlive` и `TryResetTimeout(60_000)`.

## Запись файлов и outbox

Для открытых хэндлов одного пути используется общая локальная копия `LocalFile`. Изменение существующего файла обычно скачивает исходное содержимое только при первом чтении или частичной записи. Полная перезапись с начала может обойти скачивание старой версии.

Сохранение проходит через `Persist`:

1. `Upload` — загрузить содержимое. Для файлов меньше 64 МиБ используется multipart; от 64 МиБ включительно — Upload 2.0.
2. При замене существующего облачного файла `DeleteOld` удаляет старую запись после успешной загрузки.
3. `Attach` прикрепляет новый `fileId` под исходным именем. Для нового файла шаг `DeleteOld` пропускается.
4. Если сервер возвращает бизнес-ошибку на `Attach` после удаления старой записи, движок вызывает `RestoreFromTrash` для отката.

При ошибке сохранения `Engine` сохраняет рабочие данные и переносит их в постоянный outbox `%LOCALAPPDATA%\BarkCloud.Drive\outbox\`: бинарный файл и JSON-манифест с состоянием операции. Worker повторяет отправку после входа в ту же учётную запись и на тот же сервер. Записи с `OwnerUserId=null` скрыты до усыновления аутентифицированной сессией этого сервера. Повторы ошибок outbox не ограничены числом попыток; пауза растёт от 30 секунд до 5 минут и затем остаётся 5 минут. Файл со статусом pending виден на диске и доступен для чтения, но запись, удаление и переименование запрещены до завершения отправки. `PendingUploads` показывает количество записей outbox.

Upload 2.0 создаёт возобновляемую серверную сессию, отправляет недостающие части и сохраняет состояние для продолжения после ошибки. Повторный `Resume` ограничен тремя повторами за проход только для кодов ошибки сервера `UploadSessionNotFound`, `UploadTokenInvalid` и `UploadSessionState` из поля `code` JSON-тела ответа на PUT части; прочие сетевые ошибки обрабатываются как обычные ошибки outbox. После передачи `Engine` опрашивает статус обработки сервера раз в 2 секунды, не дольше 2 минут за проход. Если обработка не завершена, запись сохраняется в outbox на стадии `Processing` и проверяется worker-ом позже. После трёх пересозданий сессии следующая попытка откладывается на час. Отмена сессии best-effort выполняется, только пока операция находится на стадии `PersistStage.Upload`.

Новый пустой файл пока остаётся локальной заготовкой `Engine`: серверная запись не создаётся. Пустое сохранение поверх облачного файла тоже не загружает пустую версию.

## Папки и приложение

Папки можно создавать, перемещать и удалять. Перед удалением `Engine` проверяет локальные записи и свежий листинг, но сервер удаляет папку рекурсивно; другой клиент может добавить файл между проверкой и запросом удаления. `MoveFile` поддерживает переименование и замену цели, а при неудаче выполняет откат.

При потере IPC приложение пытается переподключиться к движку. Закрытие главного окна сворачивает его в трей; пункт «Есть неотправленные файлы» открывает outbox. `WPF-UI.Tray` 4.3.0 не показывает balloon-уведомления, поэтому статус ошибки или число pending отображаются в подсказке значка и меню.

Настройки движка, сервера и приложения сохраняются через временный файл с атомарной заменой. Журнал `Engine` находится в `%LOCALAPPDATA%\BarkCloud.Drive\engine.log`; при размере больше 5 МиБ он ротируется в `engine.log.1`.

dotnet build Drive/BarkCloud.Drive.slnx -c Release
dotnet test Tests/Drive/BarkCloud.Drive.Engine.Tests -c Release
```

Реальный named pipe проверяется отдельно категорией `WindowsIpc`:

dotnet test Tests/Drive/BarkCloud.Drive.Engine.Tests --filter "Category=WindowsIpc"
```

GitHub Actions запускает job `Drive (Windows)` на `windows-latest` при изменениях `Drive/**`, `Tests/Drive/**`, `Shared/BarkCloud.Proto/**`, `Directory.Build.props`, `Tests/Directory.Build.props` или `.github/workflows/tests.yml`. Job собирает решение и запускает весь тестовый проект, включая `WindowsIpc`.

## Известные ограничения

- Правка создаёт новый `fileId` и заменяет старую запись. Привязанные к прежнему `fileId` избранное и ссылки Drive не переносит.
- Удаление папки не атомарно относительно изменений других клиентов: добавленный после проверки файл может быть удалён вместе с папкой.
- Разрешение имён в Windows Drive нечувствительно к регистру. Объекты, отличающиеся только регистром, нельзя адресовать независимо; при поиске побеждает первое совпадение в порядке листинга.
- Пустые заготовки хранятся только в реестре работающего `Engine` и исчезают из диска после его перезапуска. При logout или смене аккаунта пустые заготовки удаляются; заготовки с данными остаются на диске, а их путь записывается в `LastSyncError`.
- Старый токен без `ServerKey` привязывается к текущей конфигурации без проверки сервера; подробности — в разделе [«Сессия, TLS и IPC»](#сессия-tls-и-ipc).
- Читатель, открытый до сохранения правки, держит снимок со старым `EntryId` и продолжает читать старую версию. `DeleteOnClose` на таком хэндле удаляет старую запись (`EntryId`); актуальная версия остаётся.
- При завершении outbox `Engine` удаляет манифест и `.bin` отдельно. В гонке чтения возможен `FileNotFound` у читателя или оставшийся `.bin` без манифеста.
- Engine возвращает `AccessDenied`, пока `Pending` удерживается открытым читателем; после удаления манифеста завершённой отправки файл остаётся читаемым и запись недоступна до закрытия читателя.
- Мягкий лимит кеша может временно превышаться; подробности — в разделе [«Чтение и кеш»](#чтение-и-кеш).
- Если содержимое меняется во время ожидания `Processing`, прежний blob может завершить обработку без привязки; подробности о повторах и отмене — в разделе [«Запись файлов и outbox»](#запись-файлов-и-outbox).
- Перезапуск `Engine` из приложения ждёт штатного завершения до 60 секунд, затем принудительно завершает процесс. Если рабочая копия ещё не была передана в outbox, байты остаются в `%TEMP%\BarkCloudDrive\write`, но после запуска `Engine` не восстанавливает эту локальную запись автоматически. Уже помещённые в outbox файлы и манифесты переживают перезапуск и могут быть отправлены позже.
- Если закрыть приложение во время перезапуска, `App` завершается без `ShutdownAsync`; уже поднятый к этому моменту новый движок продолжит работать без UI.
- В трее нет всплывающих уведомлений; состояние видно по подсказке значка и пункту «Есть неотправленные файлы».
- В `Drive` пока нет серверной атомарной замены содержимого, отдельного пути отправки пустого файла и персистентной очереди удалений. Имена, недопустимые в Windows, не отображаются через отдельное преобразование. Инсталлятор не поставляется.
