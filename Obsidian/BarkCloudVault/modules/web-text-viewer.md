# Web — просмотр текстовых файлов

Parent: [[modules/backend-web]] · See also: [[api/files-api]]

## Контракт и открытие

`ClientApp/src/lib/textFiles.ts` содержит единый классификатор по имени, лимит `MAX_TEXT_FILE_BYTES = 10 * 1024 * 1024`, построение URL и декодирование. Поддерживаются текстовые, конфигурационные и исходные файлы, специальные имена `Dockerfile`, `Makefile`, `.env` / `.env.*`, `.gitignore`, `.gitattributes`, `.editorconfig`, `.dockerignore`. HTML и SVG показываются исходным текстом; офисные документы сохраняют прежнее открытие.

`useTextFileViewer` хранит выбранный файл и возвращает `openTextFile` / `textViewer`. В «Файлах» открытие доступно двойным кликом, из инспектора и ПКМ-меню. Избранное, умные папки, поиск (включая Topbar), «Мне доступны», общие и публичные папки открывают текст вместо скачивания. Публичная страница файла предлагает «Открыть файл». `useTextSearchOpen` подключает просмотр непосредственно к результату поиска.

Общий `components/text/TextFileViewer.tsx` использует существующий `Modal`, портал в `body`, имя и размер, состояния загрузки/ошибки/пустого файла, скачивание оригинала. Фокус возвращается после закрытия; Escape обрабатывает только последний открытый диалог. Адаптивные стили и обе темы — `styles/text-viewer.css`.

## Содержимое

До **10 МиБ включительно** загружается весь оригинал. Более крупный файл показывает сообщение и действие «Скачать». Запрос отменяется при закрытии или смене файла; JSON Worker завершается, устаревшие результаты подсветки и схем игнорируются.

Автоопределение: UTF-16 LE/BE с BOM, иначе UTF-8 (включая BOM). Можно вручную выбрать UTF-8, UTF-16 LE/BE или Windows-1251. Строгое декодирование сообщает об ошибке; NUL и высокая доля управляющих символов обозначают бинарное содержимое. Пустой текст — успешное состояние.

`TextSource.tsx` лениво загружает CodeMirror 6: только чтение, номера строк, выделение/копирование, подсветка по имени файла, переключатель переноса строк. Библиотеки языков загружаются по необходимости.

Для `.json` кнопка «Форматировать» запускает `formatJson.worker.ts`: `jsonc-parser` строго проверяет JSON и применяет текстовые правки с отступом два пробела. Написание чисел, экранирование строк, порядок и повторяющиеся ключи сохраняются. Ошибка содержит строку/столбец и оставляет исходник; «Исходник» отменяет форматирование. JSONC/JSONL/NDJSON открываются обычным текстом.

Markdown (`md`, `markdown`, `mdown`, `mkd`) по умолчанию полностью показывает разметку для всех допустимых размеров, без порога переключения на исходник. Есть переключатель «Разметка / Исходник». `MarkdownPreview.tsx` лениво подключает `react-markdown`, GFM, math, KaTeX и highlight: таблицы, задачи, сноски, код, формулы. Сырой HTML пропускается; разрешены внешние HTTP(S)-ссылки/картинки, mailto и якоря, относительные облачные пути не разрешаются. KaTeX использует `trust: false`; ошибка формулы сохраняет исходное выражение локально.

`MermaidDiagram.tsx` лениво загружает Mermaid и последовательно рендерит блоки `mermaid`: `securityLevel: strict`, защищённые настройки, HTML-метки отключены. Директивы конфигурации и frontmatter из файла отвергаются, размер/число рёбер схем ограничены. Ошибка отдельной схемы показывает её исходник и не мешает остальному документу. Тема схем обновляется вместе с темой приложения.

## HTTP-доставка байтов

`Endpoints/TextPreviewEndpoints.cs` подключён в `Program.cs`; `Infrastructure/TextPreviewProxy.cs` зарегистрирован singleton. Все ответы имеют `Cache-Control: no-store`. Формат оригинала и кодировка не изменяются.

| GET-маршрут | Проверка доступа |
| --- | --- |
| `/api/files/text?id=` | AuthGateway + пользовательский `GetTempDownloadUrl` |
| `/api/shared/text?fileId=` | AuthGateway + `GetSharedFileDownloadUrl`: прямой грант или общая папка |
| `/api/public/shares/{token}/text` | `ResolveShare`, включая отзыв ссылки |
| `/api/public/folder-shares/{token}/text?dir=&fileId=` | `ResolveFolderShare`; файл обязательно находится в списке указанного каталога |

Прокси принимает URL только от gRPC, извлекает временный download-id и загружает `/download/{id}` через внутренний `FilesService:Http1Base` (HTTP-клиент `files-upload`). Проверяется `Content-Length` и фактический поток, в том числе без заголовка длины: превышение возвращает 413 до выдачи содержимого. Отмена передаётся в gRPC, HTTP и чтение потока. Ошибки авторизации/доступа/отсутствия возвращают 401/403/404, недоступность Files — 502, таймаут — 504. gRPC и БД не менялись.

## Проверки

Frontend-тесты: классификатор/кодировки/бинарные и пустые файлы, JSON без потери лексем, Markdown и опасная разметка, отмена загрузки/Worker, вложенные модалки, открытие из всех разделов. Web-тесты: реальные HTTP-маршруты с mock gRPC, гранты/отзыв/принадлежность папке, ограничение потока без `Content-Length`, ровно 10 МиБ и превышение.

В браузере проверены реальные CodeMirror/JSON Worker, Mermaid/KaTeX, обе темы, ширина 390 px, прокрутка текста и полный автоматический рендер Markdown на 10 МиБ. Полный рендер крупного Markdown может занимать заметное время; это выбранное поведение первой версии.
