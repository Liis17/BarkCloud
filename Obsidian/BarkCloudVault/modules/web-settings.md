# Web — настройки

## Загрузка и контракты

`AppShell` получает профиль через `GET /api/me?includeStorage=false`, а статистику независимо через `/api/storage`. Обычный `/api/me` и `/api/settings/full` сохранены для совместимости. Меню, общий поиск и каркас настроек не ждут обхода диска или S3.

`SettingsPage` отдельно получает `/api/settings/context` с `admin.enabled/unlocked`, затем запрашивает только выбранный раздел:

| Раздел | GET |
|---|---|
| Аккаунт | `/api/settings/profile` |
| Хранилище | `/api/settings/storage` |
| Обслуживание | `/api/settings/system` |
| Безопасность | существующие `/api/settings/security/2fa`, `/webauthn` |
| Приватность | существующий `/api/settings/privacy` |
| Сессии | существующий `/api/settings/sessions` |
| Настройки сервера | существующий admin-only `/api/settings/server` |
| Миграция | admin-only `/api/settings/migration/sources`, `/jobs`, `/cutovers` |
| Внешний вид | локальные данные браузера |

`PageDataBuilder` использует deadline 3 с и RequestAborted для лёгких gRPC-вызовов. Сбой профиля в lean-режиме не превращается в вымышленного пользователя. Авторизация и существующие серверные проверки AdminGate сохраняются.

`useApiResource` хранит данные раздела, объединяет повторные загрузки, отменяет устаревший запрос при переключении раздела и ограничивает HTTP-запрос 10 с. Посещённые панели остаются смонтированными скрыто, чтобы сохранять черновики; запросы скрытой панели останавливаются. URL `/settings#…` сохраняет выбранный раздел, включая ссылку до загрузки контекста доступа. 401 переводит на login, 403 конфигурации возвращает к разблокировке.

## Статистика

Web устанавливает совместимый флаг `GetUserStorageInfoRequest.non_blocking_stats=true`. Files прогревает disk/S3 после запуска и хранит последний успешный замер. Истечение TTL 5 минут запускает один пересчёт на источник, не блокируя Web. Ошибка сохраняет замер и его время; остановка Files отменяет работу.

Диск и S3 имеют отдельные state/updatedAt: loading, ready, refreshing, error; S3 также not_configured. Во время первого расчёта интерфейс показывает «Подсчитываем…», без фиктивных 0%, пустого `/` и «недоступно». Первый сбой отображает ошибку подсчёта и останавливает индикатор загрузки. Последний замер остаётся при refreshing/error. `StorageStatsStatus` показывает время успеха и понятное состояние. При loading/refreshing `useApiResource` опрашивает данные раз в 3 с; скрытая вкладка браузера приостанавливает опрос, возвращение обновляет данные.

## Компоновка и поиск

Настройки занимают доступную область справа. Навигация — 220 px, обычные формы ограничены 760 px; конфигурации, обслуживание и статистика используют всю ширину. При окне меньше 1200 px раздел выбирается сверху. На узких экранах app-sidebar становится иконной колонкой. Используются существующие токены MD3, поля/кнопки 40 px, при сенсорном вводе — минимум 48 px, обе темы и видимый фокус.

Общий поиск индексирует названия разделов, пунктов и короткие пояснения. Результат открывает нужный раздел и фокусирует пункт; административные пункты доступны по текущему контексту. Значения и секреты не индексируются.

Отдельный поиск конфигураций ищет service/section/key и названия S3-полей. Совпадения подсвечиваются, нужные группы раскрываются; отдельно отображается число обычных параметров и совпавших полей/ролей S3. Очистка возвращает прежнее раскрытие. Сервисы, секции, reserved names и S3 по умолчанию свёрнуты; есть «Развернуть всё»/«Свернуть всё» и счётчики параметров/изменений.

`SettingEditor` сохраняет собственный черновик при поиске, сворачивании и обновлении соседнего параметра. Сохранение доступно только при изменениях и подтверждается диалогом; источник и restart targets показаны компактно, история загружается по запросу. Служебные `*:Token` скрыты, read-only поля недоступны.

## S3

Регион `Region` и адресация `ForcePathStyle` редактируются и сохраняются вместе с подключением; отсутствие полей старого запроса сохраняет прежние значения. Последняя вкладка [[modules/web-s3-migration]] копирует физический бакет без удаления; основные S3-настройки отдельно показывают «Применить миграцию», подтверждение всех ID профилей и восстановление долговечного барьера после рестарта Web.

`StorageSection` показывает роли, active version, endpoint, bucket и квоту; для отсутствующей специализированной роли явно показывает fallback universal. Legacy-роли выделены в отдельную группу. Редактор выбранного профиля содержит подключение, credentials, квоту и R2; при рабочей ширине меньше 800 px используется список → детали с возвратом назад.

Черновики хранятся по profileId/new:role и переживают смену роли, поиск, соседнее сохранение и активацию версии. Версии/активация/история раскрываются по запросу. Backend не отправляет raw credentials: интерфейс показывает «задан», пустой ввод сохраняет существующие ключи. Кнопки видимости работают только для вновь введённого значения.

Проверка доступа отправляет текущий черновик в `/storage/check`, ничего не сохраняя. Клиент проверяет HTTP(S) endpoint, bucket, наличие credentials при создании и целую квоту в диапазоне Int64. GB/TB/PB пересчитываются через BigInt без потери точности; пустые поля неизменённой квоты сохраняют прежнее значение на сервере. Ошибки валидации расположены у полей. Сохранение показывает перечень изменений в диалоге без значения ключей, после успеха очищает введённые credentials и показывает необходимые перезапуски.

## Проверки и выпуск

Регрессионные тесты проверяют искусственную задержку storage на 10 с: lean-профиль, context и профиль настроек завершаются менее чем за секунду при продолжающемся legacy-запросе. Отдельно проверены cold cache, stale refresh, ошибка с сохранением времени, один пересчёт при 20 запросах и остановка сервиса. Frontend проверяет независимую загрузку меню, два поиска, сохранение черновиков, S3/fallback/legacy/версии/квоты/маскирование ключей, 403 и быстрый Docker-снимок до реестра.

Реальный эпизод задержки около 10 с после рестарта/простоя требует замера в запущенном окружении: отдельно refresh токена, profile/context, Files DB, обход локальных файлов и S3. Здесь Docker отсутствует, PostgreSQL-интеграции без `BARKCLOUD_TEST_POSTGRES` пропускаются. Контрольный тест доказывает устранение блокирующей зависимости, но не измеряет production-сеть и auth-refresh.

Совместимые gRPC-поля выпускать сначала на Files, затем на Web; иначе старый Files проигнорирует non_blocking_stats и Web будет ограничен deadline вместо фонового снимка. Порядок запуска остальных клиентов не меняется.
